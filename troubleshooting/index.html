Troubleshooting

Stuck is a state. Not a verdict.

Choose the symptom. Find the next useful check.

12 diagnostic guides

Command not found

Likely causes: Installation did not finish, PATH has not refreshed, or you installed in a different environment.

Diagnose: Open a new terminal and run codex --version. In PowerShell use Get-Command codex; in Bash/Zsh use command -v codex. Check whether you are in native Windows or WSL.

Recover: Follow the installation route for that same environment. Do not repeatedly install in PowerShell to fix a missing WSL command.

Success looks like: codex --version prints a version in the terminal you will actually use.

Wrong project directory

Likely causes: The shell opened at home, a parent folder, or another checkout.

Diagnose: In PowerShell run Get-Location and Get-ChildItem. In Bash/Zsh run pwd and ls. Look for the three counter files, not only an enclosing folder.

Recover: Exit Codex, use cd with the exact extracted folder path, and start codex again. Check /status and ask it to list the relevant files without editing.

Success looks like: Both shell and agent refer to the intended counter folder.

Sign-in difficulties

Likely causes: Wrong account/workspace, incomplete browser flow, unavailable entitlement, or a managed restriction.

Diagnose: Run codex login status in the shell. Read the exact error and confirm your browser account. Check the current official authentication options.

Recover: Use codex login to retry the appropriate sign-in flow. For account policy issues, contact your workspace administrator. Do not buy API credit simply because browser sign-in failed.

Success looks like: Login status confirms access and an ordinary prompt succeeds.

Missing runtime or dependencies

Likely causes: A proposed command needs software that is not installed or is in a different environment.

Diagnose: Check the actual project README and the error. node --version checks Node; npm --version checks npm. The webpage itself does not require either.

Recover: For manual counter checks, open index.html in a browser. Install a runtime only if the course/check needs it and your device permits it. Do not invent npm test for this project.

Success looks like: The required command is present, or the blocked automated check is explicitly reported.

Permission or sandbox restriction

Likely causes: The action is outside allowed file roots, network access, approvals or managed policy.

Diagnose: Read the denied action and exact target. Check /status and /permissions in CLI. Distinguish an OS file error from an agent sandbox denial.

Recover: Move the task into the intended allowed project or request only the specific access required. Ask the environment owner about policy. Do not use bypass flags as a beginner fix.

Success looks like: A narrowly scoped permitted action works; review its result separately.

Command unavailable in this interface/version

Likely causes: A CLI example was used in an IDE/web composer, or the installed release differs.

Diagnose: Record codex --version and codex --help in the shell. Type / in CLI to inspect its actual menu. Confirm the interface label on the reference entry.

Recover: Use the interface’s supported command or natural-language task prompt. Consult official current docs before updating; managed installations may be controlled centrally.

Success looks like: The intended action is available without guessing a command name.

Agent misunderstanding

Likely causes: The request omitted the symptom, scope, constraint or completion test.

Diagnose: Compare its stated plan with your requirement. Identify the first wrong assumption: file, behavior or environment.

Recover: State the correction and a concrete example: at zero, minus must remain zero. Ask it to restate the smallest next change before continuing.

Success looks like: The revised plan and observed behavior both match the requirement.

Unexpected edits

Likely causes: Scope expanded, a formatter touched unrelated files, or existing work was misidentified.

Diagnose: Pause work, save a copy and inspect /diff or Git status/diff. Identify which edits were yours before the task.

Recover: Request a targeted correction preserving unrelated work. Avoid blanket reset/clean/restore commands. Use your known checkpoint and review recovery before applying it.

Success looks like: The diff contains only intentional changes and the project still works.

Checks cannot run

Likely causes: A tool, browser, network connection or permission is unavailable.

Diagnose: Read the actual failed command and output. Determine whether it ran and failed or never started.

Recover: Use a permitted equivalent or run the manual checklist yourself. Report automated checks as blocked, with the reason and remaining verification.

Success looks like: The handoff distinguishes passed, failed, and unperformed checks.

Code still fails after a claimed fix

Likely causes: The agent fixed the wrong state, missed an edge case, or the browser loaded old code.

Diagnose: Reload, reproduce a minimal sequence, inspect the browser console, and compare current app.js with the diff.

Recover: Supply expected versus actual behavior and exact steps. Ask for a new hypothesis supported by current code. Recheck the original bug and neighboring cases after the fix.

Success looks like: You can reproduce the successful sequence yourself after reload.

Context loss or long conversation

Likely causes: Earlier details were summarized, omitted, or belong to a different session.

Diagnose: Ask for current requirements and file references. Compare them with the current project rather than old messages.

Recover: Write a short handoff with task, decisions, state and remaining checks. Use /compact for a long CLI chat or /new plus the handoff for a fresh start.

Success looks like: The next plan uses current files and preserves your constraints.

Usage limits

Likely causes: Account entitlement, shared workspace usage, model availability or API budget constraints.

Diagnose: Read the product’s displayed limit/reset information and your sign-in method. ChatGPT and API billing are different.

Recover: Wait for the indicated reset, narrow work, or follow the account’s current supported options. Do not assume changing clients creates a new allowance. Consult your course/workspace owner when appropriate.

Success looks like: The interface confirms usable access; no unlimited-use claim is assumed.
