Project instructions

Give future sessions a useful AGENTS.md.

Prerequisites: Know how to run and check your project

Instructions that travel with the project

AGENTS.md is a Markdown file with project guidance for coding agents. Use a task prompt for today’s change, AGENTS.md for stable project expectations, and a skill for a reusable procedure selected when relevant.

For our counter, an instruction such as “no framework” should not have to be repeated every session. But AGENTS.md should describe real run and check commands, not wishful ones.

Understand discovery and scope

Codex builds guidance at session start: global guidance in its home directory, then project guidance along the path from the project root to the current directory. In each directory, an AGENTS.override.md takes precedence over AGENTS.md. Later, more local guidance overrides earlier guidance. Empty files are skipped and there is a configured size limit.

Do not assume a file in an unrelated sibling folder applies, or that changing guidance mid-session has already reloaded it. Restart and ask which instruction files were loaded when checking discovery. Exact discovery rules ↗

Write a useful first version

Goal: encode the counter’s working agreement. Where: create AGENTS.md in the extracted counter folder using your editor. This is example file content, not a shell command:

# Counter project

## Structure
- index.html: semantic page and buttons.
- style.css: layout and focus styles.
- app.js: state transitions and DOM updates.

## Run and check
- Open index.html in a browser; reload after edits.
- If Node is installed, run node check.mjs.
- Manually check +, minus at zero, Reset, and keyboard use.

## Conventions
- Use plain HTML, CSS and JavaScript; no dependencies.
- Keep count nonnegative and Reset at zero.
- Preserve native button semantics and visible focus.

## Completion
- Review all changed files.
- Report checks actually run and any blocked checks.
- Do not publish changes unless requested.

Why it helps: future sessions get the file map, real checks and completion conditions together. Likely result: the agent refers to these conventions when doing a task. Verify in a fresh session by asking it to summarize applicable guidance without editing files.

List the instruction files you loaded for this folder. Summarize the counter constraints and checks. Do not edit anything.

If it misses the file, confirm capitalization, directory and session freshness. CLI /init can scaffold guidance, but review and adapt its output before treating it as project truth.

Keep it small and current

Delete stale commands when the project changes. Put long background documents in reference files and point to them. Resolve contradictions explicitly. Avoid recording one-off task status as permanent policy. A useful test: could a new teammate follow the run/check section without guessing?

Practice: add this file after you fix the counter, then intentionally ask for a framework migration. Verify that the agent recognizes the conflict and asks for a decision rather than silently changing the project’s architecture.
