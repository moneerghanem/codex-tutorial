Reusable skills

Turn a useful checklist into a repeatable workflow.

Prerequisites: Complete Project instructions

A reusable workflow, not a magic ability

A skill packages instructions for a repeatable task. It may include references, scripts and assets. Guidance does not guarantee correctness, install a missing tool or grant permission.

A skill directory contains SKILL.md with required name and description metadata. Optional references/, scripts/ and assets/ keep supporting material separate. Start instruction-only for this exercise.

Where to put it

For the CLI counter project, create .agents/skills/counter-review/SKILL.md inside the repository. Repository discovery scans .agents/skills from the current directory up to the repository root. Personal skills use ~/.agents/skills; ~ means your home folder. Admin/system locations and managed policies can differ. Current locations and activation ↗

Build a small review skill

Goal: standardize the counter review. Where: write the following file in your editor. YAML metadata sits between the two --- lines.

---
name: counter-review
description: Review a plain-JS counter for correctness and keyboard accessibility. Use for counter review requests, not unrelated apps or implementation tasks.
---

1. Read index.html, app.js and style.css. Do not edit.
2. Check increment, decrement at zero, and Reset state.
3. Check native button names and visible focus styles.
4. If Node is available, run node check.mjs and report its actual result.
5. If browser interaction is available, check Tab, Enter and Space.
6. Report findings with file references and reproduction steps.
7. Separate observed checks from manual checks still needed.

In CLI or the IDE, use /skills or a $ skill mention to select the installed skill. If changes do not appear, restart Codex. Matching descriptions may also trigger a skill automatically; do not depend on that during testing.

$counter-review Review this project without editing it.

Likely result: a review structured around the checklist. Verify that actual file references exist, that claimed checks have output and that the agent did not edit files. If the skill is not listed, check folder spelling and metadata first.

Test guidance as carefully as code

  1. Run the review on the broken starter. Expect findings about Reset and negative counts.
  2. Run it on the completed version. Confirm it does not invent those defects.
  3. Try an unrelated request. The description should not match it.
  4. Remove browser access. The review should label keyboard testing as unperformed.

These are expected test cases, not recorded results from an actual skill run. If the review misses a bug, improve the checklist and rerun it; do not assume installing the skill solved the problem.
