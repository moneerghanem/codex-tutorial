Read what changed

A diff shows removed lines with − and added lines with +. Those symbols describe edits, not whether code is good or bad. Read surrounding logic too.

- reset.addEventListener('click', () => { render(); });
+ reset.addEventListener('click', () => { count = 0; render(); });

The new line updates state before drawing the number. Check that count is the same variable used by increment. A superficially plausible change to a different variable would not fix the bug.

Inside CLI, use /diff and optionally /review. Another AI’s review can suggest issues; it is not independent proof. Reference ↗

Make small Git checkpoints

Git records versions. A commit is a named snapshot; staging selects what goes into it. In the extracted practice folder, with Git installed, first create a repository if one does not already exist:

git init
git status
git add index.html style.css app.js check.mjs README.md
git commit -m "Save counter starting point"

Inspect git status first. Stage only files you intend to save; never stage secrets. Git may ask you to configure your name and email before committing. Use your own identity, following the message Git displays. These commands record local work and do not publish it.

After the task, inspect unstaged and staged changes:

git diff
git diff --staged
git status

git diff omits untracked files; git status tells you about them. Review each new file separately. Once checked, stage the intentional changes and commit again. Official Git tutorial ↗

Recover without losing other work

If the agent made unwanted edits, pause and save a copy of the current folder before recovery. Inspect the diff and identify exactly which changes belong to the agent. Prefer a targeted correction or editor undo for a known edit.

For a published or shared bad commit, git revert COMMIT_ID creates a new commit reversing that commit; inspect the resulting changes and handle conflicts carefully. Replace COMMIT_ID with the actual reviewed hash. Do not blindly run git reset --hard, git clean or restore commands: they can discard work. Ask for an explanation of the exact files affected before any destructive recovery.
